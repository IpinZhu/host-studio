# 框架设计

## 依赖方向

项目页面 → 通用 UI / 类型化 API → Tauri 命令 → 设备会话 / 设备模型 → 设备协议 → transport。
host-core 与 host-transport 均不依赖 Tauri。协议只解释消息，不操作 UI。

## 扩展一个设备

1. 新建设备 crate，实现消息编解码和 DeviceDriver 对应设备模型。真实异步设备应提供独立会话服务，不阻塞同步 trait。
2. 明确身份查询、版本协商、参数描述、遥测字段与单位。
3. 选择串口、TCP、UDP、USB HID 或 BLE GATT；不得假定一次 receive 返回一个协议帧。
4. 对字节流实施长度上限和错误后重新同步；对报文实施重复、乱序、分片和过期策略。
5. 为真实会话定义 Disconnected / Connecting / Handshaking / Ready / Faulted 状态机。
6. 将业务命令注册到 Tauri；从 Rust 校验所有参数，禁止原样执行前端输入。
7. 在工作台注册设备卡片和专用页面。通用参数模型后续演进为描述式 schema；当前仅 FOC 示例字段。

## 生命周期与数据

每台设备一个会话。请求必须有超时、取消与应答关联。
断连取消采集、订阅和待完成命令。重连后重新校验身份，启动电机等非幂等命令禁止自动重发。
采集、录制和绘图独立限速，队列容量有界。生产采集应由 Rust 驱动，并通过 Channel 批量推送。
当前工作台以 20 Hz 轮询演示流程；不会用于实时电机闭环控制。

## 通用界面与说明

页面从标签导航开始，不单独渲染图标、应用名称、版本和运行环境的信息栏。应用图标仍用于系统窗口、任务栏及帮助弹窗。

`src/HelpTip.vue` 是独立的说明组件，样式随组件提供，不依赖 FOC 数据模型。页面按需导入：

```vue
<HelpTip id="parameters-help" label="设备参数">
  编辑后点击“应用参数”才会生效。
</HelpTip>
```

同一页面的 `id` 必须唯一，`label` 用于按钮的无障碍名称。将问号作为字段或标题的相邻元素，不嵌套进已有按钮或输入标签。纯解释性内容可收进提示；数值、单位、允许范围、未连接状态和实际错误仍应直接可见。

提示通过 Teleport 渲染到页面顶层，避免被卡片和滚动容器裁切，并按窗口边界定位。支持鼠标悬停、键盘聚焦、点击和 Esc 收起；组件卸载时清理定时器及窗口监听。当前提示采用深色底，适用于明暗主题。

全局基础字号为 16 px，已有固定字号和 canvas 刻度较首版统一增加 2 px。侧栏、参数网格、单位标签和窄屏布局同步调整；调整字体时应一并检查 canvas，不能只修改根字号。

## 帧与身份

新设备参考协议建议包含版本、类型、请求编号、消息标识、长度、负载和校验。
设备 UID 与通信端点分离：COM 号或 IP 改变不等于更换设备。
协议与参数格式应有独立版本；不要将 Rust 内存布局直接当作线上协议。
同一设备多条链路并存时，由会话层选择唯一控制链路。

## 分阶段验收

1. 当前首版：模拟器闭环、参数校验、波形、录制导出、原生端点扫描与底层通信接口。
2. 下一步：接入一种真实设备协议，测试拔插、超时、断帧、错误参数、记录溢出。
3. 随后：第二类设备验证复用性；描述式参数、设备注册、Channel 采集、多设备和回放。
4. 最后：固件升级、签名发布、平台权限与跨平台实机矩阵。

应用模拟器和已有 FOC 固件没有线协议兼容承诺；接入前必须根据固件实际命令建立适配层。
